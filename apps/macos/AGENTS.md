# Continuité AIM

Pour tout travail sur la continuité des agents, lire d'abord
`docs/CONTINUITY_IMPLEMENTATION_PLAN.md` : audit historique, plan approuvé,
décisions, lots C00–C10, backlog et preuves.

Après chaque tâche de code, actualiser immédiatement ce document avec l'état,
les changements, les tests, leurs résultats et les limites restantes. Ne jamais
confondre code implémenté, compilation, tests simulés et qualification réelle.
Conserver les constats historiques dans les annexes et ne pas annoncer de
pourcentage global de parité.

Préserver les modifications utilisateur, notamment dans le dépôt iOS. Ne pas
remplacer/fermer l'application utilisée sans accord. Aucun appel modèle payant
avant choix explicite du fournisseur et du budget. Les références concurrentes
servent à l'analyse ; ne pas copier leur code dans AIM.
