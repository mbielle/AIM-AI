# Native client–server contract

Static source review on 2026-10-16 of `packages/AIMCore`, `apps/ios/AIM` and `apps/macos/Sources`, compared with the fresh-install `server/supabase/functions` and ordered migrations. This inventory distinguishes a compiled API from an active native UI path. Presence in source is not evidence of deployment, correct operator configuration or an end-to-end hosted installation. This source inventory is separate from the later disposable native Supabase HTTP
qualification documented in server/LOCAL_STACK_QUALIFICATION.md. No official
service, external model provider or owner credential was used.

## Required stack and inference boundary

Local profiles, local Chat/projects and direct user-key inference do not require an AIM account server. Account authentication uses the Supabase Auth SDK ([SupabaseAuthenticationBackend.swift:61](../packages/AIMCore/Sources/AIMCore/Authentication/SupabaseAuthenticationBackend.swift#L61)); native callback schemes are declared in [config.toml:14](../server/supabase/config.toml#L14).

Native text and media inference target provider endpoints directly with the user's supplied credentials. Core rejects an empty provider key and selects provider URLs in [NativeChatTransport.swift:66](../packages/AIMCore/Sources/AIMCore/Chat/NativeChatTransport.swift#L66); OpenRouter/BFL media endpoints are in [MediaTransport.swift:79](../packages/AIMCore/Sources/AIMCore/Media/MediaTransport.swift#L79) and [MediaTransport.swift:89](../packages/AIMCore/Sources/AIMCore/Media/MediaTransport.swift#L89). Mac tool turns choose provider URLs and add the supplied authorization header in [ProviderToolConversation.swift:546](../apps/macos/Sources/AIMApplication/Chat/ProviderToolConversation.swift#L546). No Supabase inference/proxy Edge Function call was found in the inspected native sources. A server-funded inference proxy is therefore **not** a missing native dependency and must not be introduced to complete this contract.

Local model transports and the separately implemented direct ChatGPT-plan integration are distinct routes; this review does not claim every route is BYOK or qualify external provider/plan approval. Core's iPhone transport rejects `.local` and `.chatgpt` in [NativeChatTransport.swift:69](../packages/AIMCore/Sources/AIMCore/Chat/NativeChatTransport.swift#L69); the Mac plan-auth implementation is [ChatGPTPlanAuth.swift:7](../apps/macos/Sources/AIMApplication/Chat/ChatGPTPlanAuth.swift#L7).

### Legacy OAuth capability

The legacy cloud connector screen is reachable from iOS Settings → Connectors → Manage web accounts ([AIMSettingsPanel.swift:192](../apps/ios/AIM/Features/Main/AIMSettingsPanel.swift#L192)). A generic build sets `AIM_LEGACY_OAUTH_BROKER_CONFIGURED=NO`; `AppEnvironment` reads the `AIMLegacyOAuthBrokerConfigured` Info value ([AppEnvironment.swift:16](../apps/ios/AIM/App/AppEnvironment.swift#L16)). The screen disables only its server-broker add menu and displays an EN/FR capability explanation ([AIMPersonalizationView.swift:219](../apps/ios/AIM/Features/Main/AIMPersonalizationView.swift#L219)). Native HTTPS/MCP connector setup is not gated by this flag.

An operator retaining a separately reviewed external/official broker can explicitly opt in through private build configuration. The flag does not implement a broker or attest its safety. The original legacy broker is not restored here; a portable broker requires reviewed secret storage, per-attempt nonce/state validation, callback binding and provider registration first.

### Current Remote security path

Current iOS refresh migrates non-v2 accounts and calls `remote_authorize_device` ([MainExperienceStore.swift:1978](../apps/ios/AIM/App/MainExperienceStore.swift#L1978)). Its legacy PIN-setting/verification entry points return `legacy_security_retired` rather than invoking Core PIN methods ([MainExperienceStore.swift:2033](../apps/ios/AIM/App/MainExperienceStore.swift#L2033)). Core `lockRemote` first revokes device-v2 authorization with an RPC, then attempts the old Edge lock call best-effort ([SupabaseRemoteService.swift:544](../packages/AIMCore/Sources/AIMCore/Remote/Networking/SupabaseRemoteService.swift#L544)). A legacy PIN handler must not be treated as the authority for new device-v2 grants.

### Optional file extraction limits

The optional `file-processor` validates the Supabase user and live account session, accepts at most 28 MiB streamed JSON / 20 MiB decoded file, and returns at most 120,000 UTF-8 text characters without truncation. It uses no provider/service-role key, OCR service, model request or storage/content mutation. Its only outbound requests are fixed authentication/session checks on the operator's Supabase origin. PDF/images/Office failures remain explicit capability results rather than fabricated extracted text. The deployment staging step and 12 isolated mocked tests are documented in [its README](../server/optional/functions/file-processor/README.md); this is optional source support, not a deployed service.

The iOS capability notice was checked on the dedicated simulator: three configuration tests and the targeted UI test `testLegacyOAuthNoticeDoesNotDisableNativeMCP` passed. The UI run used simulated account services and application private mode; it verified disabled broker addition plus the explanation, while the direct native HTTPS-connector entry stayed enabled. No real broker/provider was contacted.

## Remaining integration boundaries

- External Auth email/Apple/Google, APNs and multi-device native encrypted round trips
  still need operator configuration and physical qualification. Disposable HTTP Auth,
  Storage and command checks are recorded separately; they do not prove native apps.
- Optional `remote_peer_v1` requires its separate migration and qualification; its absence from the default chain is intentional.
- Legacy web-account OAuth and non-text legacy project extraction must either be implemented by reviewed optional handlers or explain their unavailable capability. Neither should fail through an unexplained generic network error, nor enable server-funded OCR/inference as a hidden fallback.
- Existing deployed instances require their own reviewed upgrade/retention plan. The fresh migration chain must not be replayed over an existing production database.

## Native reviewed project snapshots

iOS device-only project documents use local PDF/Office/image/text extraction and
a reviewed bounded text copy, isolated by profile. Explicit Chat inclusion supplies
that text as an untrusted user attachment, never system instructions. These device
copies do not sync or enter the profile-copy archive. The legacy account-project
upload UI separately previews extraction before explicit upload; its snapshot API
stores original bytes and the reviewed text without calling `file-processor`.
See apps/ios/docs/PROJECT_DOCUMENTS.md for the enforced quotas and current limits.
